Privacy Policy

Last updated: October 19, 2026

In one sentence: LumePane has no mandatory telemetry and no third-party analytics. The app bundles no analytics SDK. One optional anonymous usage pulse is available, is off by default, and sends at most one small request per day if you turn it on. Neeson & Sea's licence service also keeps a handful of aggregate counters — described below.

Optional anonymous usage pulse (off by default). If you enable “Anonymous usage statistics” in About, the app sends at most one POST per day to Neeson & Sea's licence service with a random installation ID, the app version, and whether the app is in trial or licensed. The service stores a SHA-256 hash of the ID, not the raw value. It sends no IP address, account, licence code, display data, settings, commands or usage history. The only purpose is an aggregate daily active-install count; turn it off and no pulse request is sent.

The counters Neeson & Sea keep. The licence service counts six events: a checkout click, an order created, an order paid, a code claimed, a success page served, and a short code redeemed — per day and per ?src= campaign tag. The counters contain no identifier: no IP address, no cookie, no device id, nothing that could be linked to a person. They exist so Neeson & Sea can tell which channel is worth the effort.

Abuse protection is separate. Requests to the order, success and retrieval pages are rate-limited. The rate-limit keys use a truncated SHA-256 of the client IP address and expire automatically: about 15 minutes for the success and retrieval pages, and 10 minutes for activation. Retrieval attempts also write an audit row containing that truncated hash, a truncated hash of the order id and the outcome; the row is kept for up to 30 days so abuse can be investigated. Rate-limit keys and audit rows are not part of the aggregate counters above.

1. What Neeson & Sea collect

No usage data unless you opt in. No third-party analytics, no event reporting, no crash-report uploads, no device fingerprinting, no advertising identifiers, no user profiling. The optional pulse above is the only usage signal and is off by default.

Licensing contacts the network in two situations: the one-time redemption of a short code (LP-XXXX-XXXX-XXXX), and the one-time device registration on first activation. Short-code redemption sends exactly two things:

Device registration: after an activation code verifies, the app contacts Neeson & Sea's own server once to register this Mac — it uploads only an irreversible SHA-256 digest computed locally from the board identifier and the model identifier, never a serial number or plaintext model string. The digest is stable for a given Mac, which is what makes the five-Mac limit enforceable; it is pseudonymous, not anonymous. After that, every launch is verified locally.

  • The short code — the 12-character code shown on the order page after payment;
  • A randomly generated device identifier — created locally as a UUID the first time you redeem a short code, and stored in the macOS Keychain. It is used for short-code redemption and for binding the local licence record. It contains no hardware serial number, MAC address, display EDID, machine name, Apple ID, or account information.

That request only asks the licensing service to exchange the short code for the long signed activation code belonging to that order. A code beginning with LP- (the long signed code) is then verified entirely offline with the public key embedded in the app. On first activation the app also registers this Mac once, as described above; after that, every launch is verified locally. The random identifier cannot be traced back to your device model.

Current status: checkout is live. Card and Apple Pay purchases are processed by Creem (Creem.io), which acts as the merchant of record for those transactions and handles card data, taxes and refunds under its own privacy policy. Neeson & Sea receives the order id, product and email needed to issue your licence. Cryptocurrency purchases remain direct through Neeson & Sea's own checkout and licensing service. A LP- activation code is verified offline.

2. What Neeson & Sea don't collect

These are things the app uses but processes only locally on your Mac. They are never uploaded:

  • display model, vendor ID, product ID, the full EDID, and physical color gamut;
  • resolution, refresh rate, the current gamma table, brightness, and color temperature values;
  • disk capacity, cache directory sizes, scan results, and cleanup records;
  • window titles and positions (needed for window layout and session restore; readable only after you grant Accessibility permission);
  • scroll wheel events and hotkey keystrokes (needed for scroll smoothing and mouse mapping).

And these Neeson & Sea never touch at all:

  • Neeson & Sea don't upload your display model, EDID, or serial number — no such code path exists;
  • Neeson & Sea don't upload session length, feature click counts, or launch counts;
  • Neeson & Sea don't record keystrokes. Scroll smoothing reads only the displacement of scroll-wheel events; the keyboard is used solely to determine the single state “⌘ is held, bypass smoothing”;
  • Neeson & Sea request Screen Recording only when you start a screenshot, scrolling capture or recording. Recordings are written only to the folder you choose; audio captured for per-app volume is processed in memory and never recorded. Full Disk Access is optional and used only for the cleanup scanner; protected directories are skipped according to macOS rules;
  • The app has no camera or microphone call. Its Info.plist explains Screen Recording, System Audio Recording and Apple Events only when those features are used.

3. What reaches the network

Apart from the items below, the app initiates no network requests. Everything is HTTPS; plaintext HTTP is never used.

1. Checking for updates

The app requests a version manifest from appcast.xml to see whether a newer version exists. That manifest is hosted alongside this website on GitHub Pages. The request contains no license key, no device identifier, and no usage data. It is off by default: it is only sent if you turn on automatic checking in the General panel (at most once a day thereafter), or click “Check for Updates” yourself.

The host, GitHub, sees your IP address, the request time, and a client identifier, exactly as any web server would. That is the host's ordinary access log, not something Neeson & Sea collect on top of it.

2. Verifying a license

This only happens when you activate. A long signed code (LP-…) is verified locally, offline, with a public key built into the app — its verification never sends a request. A short code (LP-XXXX-XXXX-XXXX) is exchanged once, at redemption, with Neeson & Sea's own licensing service:

  • Redeeming a short code: sends the short code plus the random device identifier described above, and receives the long signed code back;
  • Registering this Mac: on first activation, sends the code plus the locally computed device digest once, so a long code can be limited to five Macs; the same code on the same Mac is recognised and does not consume a second slot;
  • Long signed code: verified offline with the embedded public key. No account, no server, no periodic phone-home — the license never lapses because you were offline.

Neeson & Sea has deliberately made this offline-first: a failed re-check, a dropped connection, or a server outage never changes your license state — it only records an error. If re-checks can't get through for a long time, there is still a 7-day grace period during which everything keeps working. Until you activate, the app sends no license request at all and asks for no account.

Current status: this is live. A long LP- code is verified offline. The only licensing requests are the one-time device registration on first activation and, if you use one, the short-code redemption above; both go to Neeson & Sea's own service. Until you activate, the app sends no license request at all and asks for no account.

3. Opening the purchase page or the website

When you click “Buy” or “Visit website”, the address opens in your default browser. Payment happens in your browser, not through the app. The purchase entry point is the order page served by Neeson & Sea's licensing service; it uses the browser you already have and installs nothing.

5. Support inbox (only if you use it)

The website has an optional support window. If you send a message, it sends your email address, the topic you pick, and the message text to Neeson & Sea's own licensing service. That service stores the thread — including the email address and messages — for up to 30 days so the reply can be delivered; the thread is not a profile and is not used for analytics. Your browser stores a random thread token in local storage so you can reopen the conversation; there is no cookie and no third-party chat SDK. The service does not store the raw IP address in the thread; rate-limit counters use a truncated hash and expire automatically. Payment details, card numbers, passwords, seed phrases and private keys are never requested in the support window.

Do not send payment credentials or seed phrases. For an order, send the order id or on-chain transaction id only. The support window is an inbox, not live chat; replies are usually sent within 24 hours.

4. Optional anonymous usage pulse

This request exists only if you explicitly enable Anonymous usage statistics; the default is off. It sends a random installation ID (stored locally, not a hardware ID), the app version, and a trial/licensed flag. It is sent at most once per day, has no retry loop, and collects no IP address, account, display or activity data. The server hashes the installation ID before storage and keeps daily aggregate counts for 45 days. Turning the setting off stops all future requests; previously counted anonymous rows expire automatically.

4. Where your data lives

  • License record (license key, instance ID, activation and re-check times): the macOS Keychain, under the service name com.neeson.lumepane.license. Not a plaintext plist.
  • App settings (trial start date, interface preferences, hotkey bindings, automation rules, eye-care schedule): ~/Library/Preferences/com.neeson.lumepane.plist.
  • Cleanup quarantine and operation log: ~/Library/Application Support/com.neeson.lumepane/Clean/. Files are moved into quarantine here first, stay restorable, and permanent deletion is only offered after 30 days.
  • System permissions: Accessibility authorization is managed by macOS and can be revoked at any time in System Settings → Privacy & Security → Accessibility.

To remove everything: quit the app, then delete the two directories/files above; for a thorough job, also delete that one Keychain entry in Keychain Access. The app installs no background service or daemon, and uninstalling leaves no resident component behind.

5. Third parties

  • Neeson & Sea's licensing service (Cloudflare Workers): serves the order page, matches your payment against the blockchain, issues the activation code, and answers a short-code redemption. It sees the order number, the on-chain transaction hash and amount, and — depending on the path — a random device identifier (short-code redemption) or the one-time device digest (activation); it does not see your name or account, and it keeps no profile of you. If you buy through a channel that collects an email address, or if you use the recovery form, it also handles that address: stored with the order record (which Neeson & Sea keeps, so that recovery keeps working) so your code can be re-sent, and a truncated SHA-256 hash of it is stored and embedded in the signed code so the form can match your order without comparing raw addresses.
  • Public blockchain APIs (for example TronGrid and public RPC endpoints): the licensing service reads public chain data to confirm your transfer. No personal data is sent to them.
  • Creem (Merchant of Record for card and Apple Pay purchases): processes payment data, taxes and refunds under its own privacy policy; Neeson & Sea receives the order information needed to issue the licence.
  • GitHub: hosts this website, the update manifest, and the download. As the host it keeps ordinary access logs (IP address, time, request path).

Beyond these, the app and this website have no third-party analytics service, ad network, social plugin, or third-party font.

6. Children

LumePane is a desktop tool for Mac users. It is not designed for children, and it does not knowingly collect any information from children.

7. Changes to this policy

If a future version changes the app's network behavior — for example, adding cloud sync — this policy will be updated first, and the changelog will say what changed. Neeson & Sea will not quietly widen what Neeson & Sea collect behind a “continued use means acceptance” clause.

8. Contact
