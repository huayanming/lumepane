Verify it yourself

LumePane is a new paid app with no reviews yet, so please do not take Neeson & Sea's word for anything. Every claim on this page can be checked on your own Mac with the commands below. The outputs quoted here are verbatim from the shipped 8.0.16 build.

1. Is it really ours, and did Apple notarize it?

codesign -dv --verbose=2 /Applications/LumePane.app
  Authority=Developer ID Application: yanming hua (7P2P353LBW)
  Format=app bundle with Mach-O universal (x86_64 arm64)
  flags=0x10000(runtime)

spctl -a -vv -t exec /Applications/LumePane.app
  accepted
  source=Notarized Developer ID

xcrun stapler validate /Applications/LumePane.app
  The validate action worked!

The binary is signed with Neeson & Sea's Developer ID, Apple scanned and notarized it, and the notarization ticket is stapled to the app so it validates offline. A modified copy fails all three checks.

2. Did the download arrive intact?

shasum -a 256 ~/Downloads/LumePane-9.7.0.dmg
  fa508820ab2ae959d281959613a322941f27f0137bbd38316ce29b597af35f32

The same value is published in the Homebrew cask, so there are two independent places to compare against:

brew cat huayanming/tap/lumepane | grep sha256

If your value differs, do not run the file.

3. Does it phone home?

The app's own code contains two endpoints on Neeson & Sea's licence service: /api/redeem, called only when you paste a short code, and /api/pulse, called at most once a day only if you turn on anonymous usage statistics. The long LP- code is verified entirely offline and never touches the network. Update checks are off by default (SUEnableAutomaticChecks is false). Automatic downloading is opt-in: SUAllowsAutomaticUpdates permits it, but remains false until you turn it on in the panel; then it only fetches appcast.xml and the signed update from Neeson & Sea's site.

Watch it yourself — open the app, leave it idle, then:

lsof -i -P | grep -i lumepane

With update checks off and anonymous usage statistics off (the default), this prints nothing. The app sends no crash reports and no identifier to Neeson & Sea; the optional pulse is the only usage signal, and it is off until you enable it.

4. Does activation really work without a network?

Turn off Wi-Fi, paste a long LP- code into the licence field, and it activates. The key is embedded in the app: an Ed25519 public key verifies the code locally, and the code is not bound to a device.

5. What you cannot check this way

  • Whether the cleanup logic is correct. It touches only 13 kinds of rebuildable artifacts and quarantines for 30 days first. Neeson & Sea publish the reasoning and the checks in the audit report rather than asking you to trust the UI.
  • Whether the display work is right for your panel. That is what the 14-day trial is for.
  • Whether Neeson & Sea is pleasant to deal with. No page can prove that. Email Neeson & Sea and see.

If any command above does not produce the output shown, that is a bug in Neeson & Sea's documentation or in Neeson & Sea's build — tell Neeson & Sea at Support and Neeson & Sea will fix it, publicly.

How Neeson & Sea audits this product (and what Neeson & Sea got wrong)

The scrolling numbers on the front page

The front page quotes a measured improvement in scroll response. That measurement comes from the app's own offline benchmark, which you can run yourself — it drives the interpolator frame by frame with a fixed timestep, without intercepting any real input, and prints the response shape:

LumePane --scroll-selftest

On Neeson & Sea's test panel (120 Hz) the first frame went from 3 to 9 points and time-to-90% from 150 ms to 133 ms. Those numbers describe the algorithm's response, not your hardware, so expect your own run to differ.
