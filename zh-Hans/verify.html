自己验证

LumePane 是还没有评价的新付费应用，所以请不要信尼森与海的话。这一页的每条说法，都可以在你的 Mac 上用下面的命令亲自核对。这里引用的输出，逐字来自已发布的 8.0.16 版本。

一、它真的是尼森与海的吗？Apple 公证过吗？

codesign -dv --verbose=2 /Applications/LumePane.app
  Authority=Developer ID Application: yanming hua (7P2P353LBW)
  Format=app bundle with Mach-O universal (x86_64 arm64)
  flags=0x10000(runtime)

spctl -a -vv -t exec /Applications/LumePane.app
  accepted
  source=Notarized Developer ID

xcrun stapler validate /Applications/LumePane.app
  The validate action worked!

这个二进制用尼森与海的 Developer ID 签名，Apple 扫描并公证过，且公证凭据钉扎在应用内，因此离线也能验证。任何被改动过的副本都过不了这三项。

二、下载的东西完整吗？

shasum -a 256 ~/Downloads/LumePane-9.6.0.dmg
  3091a943e8f5fc616ebc9ee845c89832c71681692e88de0aa3a9d45711ce9bdc

同一个值也写在 Homebrew cask 里，所以你有两个独立的地方可以对照：

brew cat huayanming/tap/lumepane | grep sha256

如果对不上，不要运行这个文件。

三、它会偷偷联网吗？

应用自己的代码里有两个网络端点，都在许可服务上：/api/redeem 只在粘贴短码时调用；/api/pulse 只在你主动开启「匿名使用统计」后每天最多调用一次。以 LP- 开头的长码完全离线校验，永不联网。自动检查更新默认关闭（SUEnableAutomaticChecks 为 false）。自动下载是显式选择：SUAllowsAutomaticUpdates 允许开启，但默认仍为 false；你在面板里打开后，它只从尼森与海站点取 appcast.xml 和签名更新包，不取别的。

你可以自己盯：打开应用、让它空闲，然后在终端里执行：

lsof -i -P | grep -i lumepane

在关闭自动更新检查、且匿名使用统计保持默认关闭时，这条命令什么都不输出。应用不会自动发送崩溃报告或标识符；唯一的可选使用信号是默认关闭的匿名统计。

四、断网也能激活吗？

关掉 Wi-Fi，把长 LP- 码粘进授权框，它会激活。公钥内嵌在应用里：用 Ed25519 在本机验签，且激活码不绑定设备。

五、这一页验证不了什么

  • 清理逻辑对不对。它只处理 13 类有确定性重建方式的产物，先隔离 30 天。尼森与海把推理与检查写在审计报告里，而不是让你相信界面。
  • 显示器那部分对你的面板是否合适。这正是 14 天试用存在的意义。
  • 尼森与海好不好打交道。这没有哪一页能证明。发封邮件试试。

如果上面任何一条命令的输出与这里写的不一致，那是尼森与海的文档或构建有问题——请到支持页告诉尼森与海，尼森与海会公开修正。

尼森与海怎么审查自己的产品（以及尼森与海错在哪）

首页上的那个滚动数字

首页引用了一组实测的滚动响应改善。它来自应用自带的离线基准，你可以自己跑——它用固定的时间步逐帧驱动插值器，不拦截任何真实输入，然后把响应形状打印出来：

LumePane --scroll-selftest

在尼森与海的测试面板（120 Hz）上，首帧从 3 点提升到 9 点，90% 用时从 150 ms 降到 133 ms。这些数字描述的是算法的响应，不是你的硬件，所以你自己跑出来的会不一样。
