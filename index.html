Frame-by-frame scrolling, dimming that doesn't depend on panel firmware, calibration anchored to the curve the app reads at takeover — and a cleanup path that quarantines before it deletes.

01 · Smooth scrolling

One notch, split into a stroke

A wheel notch stops being a single jump. Events are accumulated, then delivered on every display refresh — each frame emitting pending × (1 − e^(−dt/τ)). Because the decay is driven by elapsed time rather than by frame count, the response shape is set by time, not refresh rate; total conservation is measured at 60, 120 and 144 Hz. In Neeson & Sea's offline benchmark, the first frame at 120 Hz improved from 3 points to 9, and time-to-90% fell from 150 ms to 133 ms.

Run the free browser scroll test → It measures wheel-event gaps and dropped frames without installing anything.

Windows that treat the wheel as a precision input or a zoom control — terminals, image viewers, slide decks — are handed back to the system by default. Hold ⌘ at any time to return to native scrolling. Smoothing ships off: it never takes over your wheel unless you turn it on. The interface keeps four live counters — seen, gesture, intercepted, delivered — so when a new mouse misbehaves, you can see exactly which layer is dropping it.

02 · Software dimming

Dim without touching panel firmware

Brightness runs through the CoreGraphics gamma table, so it works even on monitors that don't implement DDC/CI. After a resolution change or wake, the app rewrites the curve and checks one interior sample against the intent; on a mismatch it retries, up to four attempts in total. Resolution changes and wake-from-sleep replay the curve automatically, so it never silently stops working.

Run the free display test patterns →

Replays always recompute from the baseline captured at takeover rather than from the current curve, so repeated adjustment can't accumulate error. At 60% brightness the mid-gray point moves from 0.5020 to 0.3012 — exact scaling, not an accumulated delta. macOS restores the display when the process exits, and there are two further recovery paths: one inside the app, and Scripts/restore-dimming.sh.

03 · Color calibration

Anchored to the curve read when the app first takes over

Contrast pivots on mid gray, gamma works the midtones, and color temperature spans 2700–9000 K — all three computed from the curve the app reads when it first takes over. 6500 K is anchored as the identity transform, so the default state is exactly how your display already looks.

The physical gamut is read straight from the EDID and drawn as a CIE xy triangle, placed next to its coverage of sRGB and Display P3. What can align, aligns; the parts the panel physically cannot reach — high-saturation red and green — are labeled as out of reach instead of faked. One click hands calibration back to ColorSync.

04 · Safe cleanup

Quarantine first. Delete later.

It only touches 13 categories of artifacts that have a deterministic way to be rebuilt: Xcode DerivedData, SwiftPM, CocoaPods, npm / pnpm / Yarn, Go, Gradle, Rust target, __pycache__, crash reports, Homebrew caches, and the like. Anything removed is moved into quarantine first. It stays restorable, and permanent deletion is only offered after 30 days.

Permanent deletion is off by default. Exactly one function in the whole app can do it, and it proceeds only when six conditions hold at once — fail any one and it aborts. The app doesn't request Full Disk Access; system-protected directories are skipped per macOS rules. Automation rules can pre-scan, never delete.

Switch the output, mute it, or change hardware volume on the panel itself when it speaks DDC/CI. When the display sleeps, the app can mute the system output and restore the previous state on wake.

The pointer knows which screen it is on

A 4K panel and a 1080p panel need different pointer speeds. The app remembers one per display and applies it when you cross screens. Acceleration, wheel behaviour and button mapping are set once, globally.

Built to be checked

The app is sold on claims that can be verified. Here is what it actually does with your data — and how to check that yourself.

  • Offline verification. A long LP- code is verified with Ed25519 against a public key inside the app. The only request at activation is the one-time device registration described next; after that every launch is verified locally, and update checks stay off unless you enable them.
  • One registration, then silence. On first activation only, the app sends an irreversible SHA-256 digest, computed locally from the board identifier and the model identifier, to Neeson & Sea's own licensing service — that is how a long LP- code can be limited to 5 Macs. No serial number, plaintext model string, MAC address, display EDID, account or usage data is sent.
  • No telemetry. No analytics, no cookies, no third-party fonts, no background service. This page makes no outbound requests.
  • The checks ship with the app. Self-tests are part of the binary, and the audit page lists what each one asserts. If a claim here ever stops being true, one of them goes red.
